## 已克隆仓库：更新

先进入另一台电脑现有仓库，确认 remote 指向此 Gitee 仓库，并检查工作区：

```powershell
git remote -v
git status
```

如果有本地改动，先单独提交或备份；不要用强制重置覆盖。工作区干净后，根据实际 remote 名更新：

```powershell
# 常见情形：另一台电脑从 Gitee 克隆，remote 名为 origin，分支为 master
git switch master
git pull --ff-only origin master
```

如果 Gitee remote 名叫 gitee，将上面的 origin 改为 gitee。若默认 origin 指向 GitHub 上游，不要从它拉取本地应用改动；可以显式拉取本仓库：

```powershell
git pull --ff-only https://gitee.com/zhang-jiashun2/local-research-agent.git master
```

若提示无法快进，保留现场并检查分支/本地提交，不要加 --force 或 reset --hard。

更新后停止旧的本地研究服务，再重新启动，让 Python 加载新代码；浏览器用 Ctrl+F5 刷新。首次读取旧数据库时会兼容性补充语言列，旧记录语言显示“未记录”，原报告文本不改写。

## 新电脑：首次运行

```powershell
git clone https://gitee.com/zhang-jiashun2/local-research-agent.git
cd local-research-agent
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-local.lock.txt
.\.venv\Scripts\python.exe -m pip install -e . --no-deps
Copy-Item -LiteralPath .\local-model-connection.example.json -Destination .\local-model-connection.json
```

安装需要网络，模型服务需要事先准备。若已有环境，不需要重新创建虚拟环境；本次没有新增第三方依赖。

编辑本机 local-model-connection.json，填写实际 OpenAI 兼容接口 base_url 和当前已加载的 model ID。模型 ID 应与该服务 /v1/models 的列表一致；换电脑后不能假定地址和名称相同。此配置文件受 Git 忽略，更新代码时保留现有配置，不重复覆盖。模型权重、API 密钥、数据库和历史报告不会随源码同步。

```powershell
.\.venv\Scripts\python.exe -m uvicorn local_app.api:app --host 127.0.0.1 --port 8765
```

打开 http://127.0.0.1:8765/。选择中文、填入主题和 1—5 个公开 HTTPS 页面链接后生成新报告；旧英文历史报告保持英文。GET /health 仅表示应用在线，不表示模型或外部网页已可用。

## 限制

当前读取 HTML 和纯文本，不解析 PDF 或依赖 JavaScript 的页面空壳。不宣称支持任意网站、完整浏览器控制、多 Agent、向量 RAG、长期记忆或已验收的自动全网搜索。公开地址检查不是完整的 DNS 重绑定防护。数据库、报告、模型配置请按需要在电脑之间另行备份和迁移，不经 Git 上传。
